# AgentCC 1.6：容量驱动的通信结构编辑

这一版扩大的是通信方案的搜索空间：从固定二叉结构上的改路、提前转发，扩展到并行通道路由和多路阶段合并。LLM提交具体结构编辑，程序负责容量计算、语义编译和独立回放。没有训练神经网络，不依赖GPU，也不把拓扑名称当作算法开关。

## 1. 当前输入与容量模型

节点、方向、边容量、共享资源及成员边完全来自本次输入。资源可以重叠，同一路径可以多次占用同一资源。设路径p对边或共享资源j的占用次数为a[j,p]，承载字节为b[p]，容量为C[j]，则：

```text
B[j] = Σp a[j,p] × b[p]
T_round = max(
    max_packet(路径开销 + 包字节数 × Σpath(1 / 边带宽)),
    最大路径开销 + max_edge_or_resource(B[j] / C[j])
)
T_communication = Σround T_round
```

这对应[公开共享资源规范](materials/spec/SHARED_RESOURCES.md)与[输出规范](materials/spec/OUTPUT_FORMAT.md)。内部计算用微秒，solution.metrics用秒。容量决定一轮所需时间，不额外规定“一秒一轮”，也不把多张卡的链路一律平均分配。最终权威仍是官方Judge。

师兄论文的容量建模建议落实在上述资源占用矩阵中。相较固定均分，实际负载累计能表达不均匀流量、重叠资源和同一路径重复使用共享池。

## 2. 先扩大合法路径空间

1.5主要改变最短路的资源权重，并在有工作量预算的路径目录里调整。不同权重可能持续选中同一条通道；尤其多层交换网络，直接边和单交换机路径不能覆盖全部并行通道。

[src/fabric_routes.py](src/fabric_routes.py)从每个源rank的实际接入交换机建立有向交换机路径树，按目标出口组成合法路径；少接入端口时，额外考察最多8个实际第二跳。交换机路径树在同一次请求中复用，rank不作为路径中继。每条路径预编译边和共享池的占用次数，逐批分配负载时优先降低整轮预计耗时，以局部峰值和负载平方增量打破平局。

目录最多16个接入口、32,768个rank对、2,000,000次交换机边松弛；这些是工作量上限，不能补出未声明的连接。超出结构目录预算时，保留原有合法控制与就绪转发编辑。实际资源成员和容量仍参与完整回放。

该分配是有界贪心，不是多商品流的全局最优解。丰富路径目录也不保证某个贪心结果必然更好，因此结构候选必须与本次实际控制方案比较。

## 3. LLM编辑通信结构

对2的幂次rank数，编号的二进制维度表示逻辑通信关系，与物理拓扑名称无关。宽度w的阶段将w个相邻二叉维度融合为一个2^w路交换阶段。生产范围w≤3，即最多8路；输入rank顺序与按实际带宽亲和力生成的顺序先以二叉容量成本比较。

AllGather在一个融合阶段中，每个发送者把阶段开始时已经持有的数据直接发给该组需要它的伙伴。它不依赖同轮新收到的数据。AllReduce则把互不相交的贡献集合归并到阶段根节点，在所有归约结束后反向广播完整结果。

为避免模型输出互相冲突的编辑，将维度分成互不重叠的小区段。AG较大的区段靠后、AR靠前，对应两者通信量沿阶段的变化。对三维区段提供四种具体改写：

| 指令 | 编译后的阶段宽度 | 含义 |
| --- | --- | --- |
| keep | 1,1,1 | 保留三个二叉阶段 |
| left | 2,1 | 合并前两个阶段 |
| right | 1,2 | 合并后两个阶段 |
| all | 3 | 合并整个区段 |

二维区段仅有keep/all，一维仅有keep。模型看到的是当前任务、代表性有向边/共享容量以及每种实际改写的容量成本，输出例如`["all","right","all"]`。这改变具体通信伙伴、数据归属表达式和轮数，不是只返回“ring/tree”等算法名称。输入摘要约取四位有效数字；最后判断使用未舍入的容量和完整拓扑。

当该目录的预计收益不足初解的5%，采用原有的就绪转发编辑接口：模型输出每个复制轮提前0、半量或全部完整原子的数量指令。这是基于当前计算结果的接口选择，不是按实例名字套用答案。两个接口每次请求只调用一个，正常为一次真实模型请求。

模型提出的程序按原样解释。名称与整数索引、全体单元素列表包装、裸数组与单独bands对象是明确支持的语法别名，不修改指令含义；未知名称、越界、布尔值、混合/多元素包装和多余字段被拒绝。不会把错误答案偷偷换成确定性最优编辑。

## 4. 编译正确性与非退化边界

**AG归纳不变量。** 在第i个逻辑维度完成后，每个rank拥有对应2^i个源的原始分片。融合w维时，接收的2^w−1份源集合与自己的集合两两不交，均在发送方轮初存在；合并后恰好覆盖2^(i+w)个源。所有维度完成后覆盖全部rank，不重复贡献。

**AR归纳不变量。** 每个阶段根持有本组的贡献，送入根的各分支贡献集合两两不交。融合只改变一次归并包含的分支数量，不改变贡献的来源和分片槽位。反向copy仅传播完整sum，并按已构造的层级展开。部分贡献不能作为完整结果提前广播。

上述构造论证不代替验证。每个可能胜出的完整候选仍通过[src/replay.py](src/replay.py)，检查方向、路径内部节点、共享资源占用、轮初持有状态、重复接收、AR贡献集合、最终结果、切分与轮数。

设本次有效控制为C，模型程序编译结果为F，仅当F完整合法且T(F)<T(C)才采用。控制保留1.5的构造/改路/分包流程，并比较新的二叉并行路径基线。因此拒绝错误模型编辑不会破坏可行性，也不会为保留模型动作强行接受通信退步。

保证仅相对于**本次控制方案与公开时间模型**，不等于跨版本逐例无退步、官方总分必涨，或模型回复之间完全一致。1.5的模型也可能找到本次控制以外的收益。

## 5. 候选准备、输出成本与稳定性

[src/stage_program.py](src/stage_program.py)在调用模型前只保存每对发送方/接收方的原子数、路径及容量成本，不构造未采用候选的全部分片字符串和JSON。模型选定后才生成完整贡献表达式与transfer。二叉基线未优于控制时也不生成其完整输出。

输入顺序和亲和顺序共享本次请求的路径容量编译；接入交换机与出口成本相同的rank复用交换机内部路径，端点边及其带宽仍各自计算。缓存只活在本次实际图中，不缓存实例答案。固定回复对照核验该优化前后的调度内容一致。

路径分配先以最多四份完整原子包计算。完成整轮负载分配后，只有在合并后的最大包路径时间仍不超过既有整轮时间时才合并包。路径与总字节不变，共享资源负载不变，包时延上界不增；这减少输出条数和序列化成本，不以少算通信换取速度。

控制计算与模型请求重叠。完整延迟应直接测量：

```text
请求前处理 + 候选容量准备 + max(模型请求, 控制计算) + 编译/回放/完整响应
```

模型总时长与CPU存在重叠，不能全当成可消除的等待。Token也不能按固定token/s换算整个请求，更不能从历史不同版本测量推出“每少1000 Token增加几分”。对照同时记录通信、完整请求、CPU、输入/输出Token、响应字节、原始模型回复和调度哈希。

固定遍历和工作量预算减少程序波动；温度0不保证模型完全确定。固定真实回复重放与真实API多次重复分别测试，避免把模型变化、程序变化和服务等待混为一谈。不会缓存固定实例的完整答案。

## 6. 理论来源与可以核验的贡献

[SmartCCL论文](materials/research/2026085860-1.txt)启发了容量建模、生成转发提案后集中去冗余/调整时间步的两段式设计。本项目不复现其神经网络；以合法控制代替学习式提案生成，以LLM具体改写和严格编译探索后处理。师兄建议中的长上下文优势是研究方向，当前短上下文实测不足以证明该机制优于传统优化器。

[TACCL](https://www.usenix.org/conference/nsdi23/presentation/shah)的通信草图启发了“受约束的结构意图→具体调度”；[ForestColl](https://arxiv.org/abs/2402.06787)提示应从完整图容量与通信结构考虑瓶颈；[TACOS](https://arxiv.org/abs/2304.05301)提供了自动合成集合通信方案的另一种思路。这些论文各有建模假设，其性能或最优性保证不能直接移植到本题的同步轮次、包延迟与重叠共享资源模型。

本项目可核验的实现贡献是：实际拓扑的多通道发现、统一资源占用预览、模型编写有明确语义的阶段改写、延迟生成完整方案，以及保持成本上界的数据包合并。离线目录最优、零编辑与模型回复对照说明各模块的作用；不会把全部路线优化收益归功于LLM。

区段边界、w≤3、固定分片策略和有限路径目录仍限制搜索空间。确定性动态规划可在给定有限阶段表上算出目录最优，模型未必优于它；目录最优也不是全局通信最优。专家与Token复核合占综合成绩30%，不等同于专家主观分单独占30%。因此材料以真实证据、规则一致性和局限为基础，不以包装替代实测。
