# AgentCC 1.9 · 1.6 调度流程的 C++ 版本

按用户要求保留 1.6 的候选构造、模型提示词、具体调度编辑与独立 Replay，将路径容量编译和逐轮路径分配的数值循环迁移到 C++。官方 AgentHack 运行时和业务编排仍用 Python。它是后续 1.10 的回退基线，不继承 1.7 的长代码生成请求。

## 实测

14 个公开样例，两版各重复两次。使用官方 Python 3.11 / AgentHack SDK，通过完整 ASGI 请求测量，单 CPU、1 GiB 地址空间，版本轮换，结束后独立 Replay。下表为请求等权平均，不是平台成绩。

| 测试 | 指标 | 1.6 | 1.9 |
|---|---|---:|---:|
| 固定原始模型回答 | 完整请求秒 | 2.1844 | 1.9964 |
| 固定原始模型回答 | CPU 秒 | 2.1796 | 1.9921 |
| 真实官方模型 | 完整请求秒 | 3.4716 | 3.4835 |
| 真实官方模型 | CPU 秒 | 2.2018 | 2.0286 |
| 真实官方模型 | 模型请求秒 | 2.3287 | 2.5195 |
| 真实官方模型 | Token 折合每14例 | 5,143 | 5,146 |

两组均 56/56 有效。固定回答组的提示词及最终调度全部一致，计算下降约 8.6%。真实模型组完整请求基本持平，模型等待掩盖了本地计算的改善；不能宣称端到端已经加速。每个真实请求一次模型调用。

428 项官方环境回归通过，3 项因可选测试条件跳过。最初失败来自独立快照缺少公共资料、测试子进程加载器与旧版本断言；修正测试工具后通过，失败日志保留便于核验。正式源码不携带 Key、模型回复、固定实例答案或运行时归档。

## 构建与使用

```bash
docker build --platform linux/amd64 -t agentcc-team:1.9 /home/czy/agentcc/artifacts/v1.9/source
docker save -o /home/czy/agentcc-images/agentcc-team-1.9.tar agentcc-team:1.9
```

平台仍使用原有官方模型配置。入口为 `python -m src.server`，最终执行 `AgentRuntime(MyAgent()).run()`；最终镜像强制加载 C++ 扩展，不能静默回退。

本版保留 1.6 的实质调度编辑，但不声称实现了新增通知所鼓励的运行时求解器代码生成。后续 1.10 同时处理模型参与证据和通信优化；新通知的具体专家评分细则尚未完整公布。
