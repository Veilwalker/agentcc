# 局部调度编辑的模型与验证边界

本版让 LLM 在当前方案的具体通信瓶颈上选择联合分流数量。模型面对的是同一上下文中的多轮负载、共享资源、合法备用路径和可移动分片数；其输出会改变实际提交方案中的传输路径。没有引入需要离线训练的神经调度器。

设计动机是让模型利用跨约束的信息选择联合动作。模型是否比确定性优化更好，以及收益是否来自长上下文能力，需要实验回答。完成一次真实模型调用、得到一次改善，均不能单独证明这些结论。

## 官方计时模型

依据 [共享资源规范](materials/spec/SHARED_RESOURCES.md) 和 [输出格式](materials/spec/OUTPUT_FORMAT.md)，一轮由若干 Rank 到 Rank 的完整路径传输组成。设每 Rank 数据量为 D，切分数为 S，每个原子分片大小为 b=D/S。AllGather 传输负载等于原始分片个数乘 b；AllReduce 负载等于唯一规约槽位数乘 b。一个包含多个贡献者的规约表达式仍是一个槽位的数据。

以下时间统一为秒，容量统一为 B/s。对传输 i，记其实际负载为 q_i，路径为 P_i：

```text
h_i = (startup_us + 中间交换机数 × switch_overhead_us) / 10^6
H   = max_i h_i
B_e = Σ_{i: e 在 P_i 中} q_i
B_r = Σ_i m_ir × q_i
```

m_ir 是路径 P_i 上绑定资源 r 的边数。同一条路径经过该资源的两条边，必须计两份负载。一条边属于多个资源时，各资源分别计入完整负载；不存在按资源个数分摊的规则。相同有向节点对重复声明的基础带宽先相加，资源绑定按集合处理。

```text
T_k = max(
    max_i [h_i + q_i × Σ_{e 在 P_i 中} 1/C_e],
    H + max(max_e B_e/C_e, max_r B_r/C_r)
)
T = Σ_k T_k
```

轮长由该式计算。带宽不是每轮固定的字节硬上限，也没有默认的交换机带宽均分。若内部使用固定时长 Δ 来检查本轮是否能完成，除了完整路径时间不超过 Δ，还须满足 B_e≤C_e(Δ−H)、B_r≤C_r(Δ−H)。单独使用 C_eΔ 会遗漏启动、交换、完整多跳路径和共享资源约束。

SmartCCL 的文本使用离散时步容量生成动作，但随后也进行动态时步调整。本项目借鉴“提出动作后集中校正”的结构，计时与状态始终采用 AgentCC 的规则。论文目前主要实验对象为 AllGather，其 32 节点 GPU 推理结果不能直接推断本赛 256 Rank、1 CPU 环境中的效果。详见 [论文摘录](materials/research/2026085860-1.txt)。

## 实际可编辑的内容

`src/schedule_edit.py` 从一个已通过本地 Replay 的方案提取有限个互不重叠的组。每个成员绑定固定轮次、原传输编号和一条当前合法的备用路径。目录可以包含不同 src/dst，但每个成员自己的端点、动作和原子数据保持不变。

公开给模型的结构包括基线标识、轮次成本、相关资源容量与负载、组的数量上限和路径示例。当前实际请求让模型按目录组顺序返回数量数组，例如两个组时：

```json
{"base": "当前目录给出的标识", "counts": [12, 7]}
```

客户端检查数组长度和整数类型后，按固定组顺序无损解码为编译器使用的 `edits: [["g0",12],["g1",7]]`，数量范围由编译器再次检查。解码不补全、不修剪、不更换数量，也不执行优化；原始数组、原始响应和规范化编辑分别留证。显式 `edits` 格式仍兼容，用于回归和旧响应。

每个数量表示按固定成员顺序移动多少个完整原子分片。移动可能在一个 transfer 内结束，此时编译器把该 transfer 分成两个互不重复的分片集合，分别走原路径和备用路径。AllReduce 的整个贡献表达式作为原子项移动，不拆开贡献者。

这定义的是模型编辑候选。服务选中该候选后，还会运行一次有预算的最终改路：模型已经移动的那些前缀传输被逐条冻结，其他传输仍可调整。冻结包含路径、完整原子表达式、端点和动作；最终阶段不能撤销这些已移动前缀，但可以移动组内其余分片。因此模型提议的数量不一定等于最终沿该备用路径传输的总数量，零数量也不禁止后续确定性阶段改路。

组内按照完整资源负载差分和交换机间边差分分组，所列 `effects` 对任意合法移动数量都是线性的。终端边上的变化还依赖前缀具体包含哪些成员，因此目录另给路径与边负载的界限，最终接受仍由完整 Replay 决定。模型没有权限创建任意边、路径、分片、轮次或规约动作。

当前动作不把传输移动到其他轮次，资源负载也不跨轮累计，因此不同轮次的编辑优化可以分开求解。实际需要联合考虑的耦合主要发生在同轮多个组使用相同资源时。一次输入多轮信息本身不能证明长上下文是必要条件。

## 可验证的性质

在输入和基线未变、私有编辑上下文有效的前提下，这种路径编辑保持以下性质：

- 对每一个 `(round, action, src, dst, 原子分片表达式)`，编辑前后的出现次数完全相同。已有数据依赖、重复接收约束和 AllReduce 贡献集合保持不变。
- 新路径仍以相同 Rank 为端点，中间只含交换机，节点不重复，每一跳是当前声明的有向边。交换机没有跨轮存储行为。
- 切分数、初始持有关系、最终分片要求和非空轮数不变。部分移动增加的是同轮中的传输条目，不会增加通信轮次。
- 应用前重新计算实时任务、拓扑语义字段和完整基线的哈希。仅比较旧的 `Topology.input_sha256` 不足以发现内存中已经发生的容量变化。
- 所有组先作为一个联合候选编译并完整 Replay。结构错误或非法方案整体拒绝，不能通过丢弃部分错误来补救。对于合法候选，逐轮保留比基线严格改善的整轮，其他整轮恢复基线；保留轮内的模型数量和路径完全不变。恢复后再次完整 Replay，没有有效改善则返回基线。

最后一条保证本地 Replay 通信耗时不变差，不保证全局最优，也不保证比赛总分不变差。模型等待、目录提取、序列化和验证均增加请求耗时。保证官方合法性的前提还包括本地验证器与官方规则一致；公开样例与对抗测试提供验证证据，不替代官方 Judge。

审计证据区分模型请求的动作、候选中尝试编译的动作、最终接受的动作，以及候选成本和真实返回成本。完整变更清单记录轮次、原传输编号、移动数量和前后路径。拒绝一次提案时不能将其记为已提交的改进。

服务再逐轮比较通过编辑器的候选与模型等待期间产生的确定性改路候选：某轮模型候选更快就采用该轮，否则采用确定性候选，合并后完整 Replay。这避免模型对一轮的有效改善被确定性方法在另一轮的大幅改善掩盖。

`model_edit.accepted` 表示至少保留了相对冻结基线有效改善的模型轮次；`model_edit.selected` 表示其中至少一轮又胜过对应确定性轮次，进入最终改路之前的合并方案。`selected_rounds`、`selected_edits` 与 `selected_frozen_transfers` 只包含这部分最终选中的动作。`preserved_in_final` 表示这些已选移动前缀在后续改路后仍逐条保留。`preservation_scope="moved_prefixes"` 明确限定这个保证，不保证完整分流比例保持原样。`accepted=true, selected=false` 不表示模型动作被采用。

成本证据也区分各阶段：`proposal_time_us` 是原始联合模型候选成本；`after_us/returned_us` 是编辑器按轮恢复后的实际返回成本；`selected_time_us` 是与确定性候选逐轮合并后的成本；`final_time_us` 是最终改路后的提交成本。原始请求保持不变，不能把筛选后的动作列表冒充模型最初的完整输出。

`candidates` 历史里只有一个记录的 `selected` 为真，它才是最终方案记录。合并记录同时保留模型基线父记录和确定性候选的来源。最终改路又有收益时，最后记录的来源是 `route_finish`，父记录可能是 `model_edit`；此时模型动作仍可能被保留，不能因为最后一步是确定性改路就抹去其贡献，也不能把所有后续收益归给模型。最终提交成本以响应中的完整 Replay 和这条唯一选中记录为准。

## 按轮筛选与组合为什么成立

对任意原始轮次，基线、模型编辑和确定性改路都保留相同的原子数据动作多重集合。路径与同轮分包不改变该轮开始时要求的数据，也不改变轮末的持有集合或规约贡献集合。因此从相同初态出发，逐轮选择任一候选的完整轮次，归纳可知每轮开始与结束的数据状态均保持一致。交换机不跨轮保存数据，资源负载也不跨轮累加，所以成本可以逐轮相加。

忽略浮点容差时，令基线、模型、确定性候选在第 k 轮的成本为 b_k、m_k、c_k。按基线筛选得到 f_k=min(b_k,m_k)，与确定性候选合并得到 u_k=min(f_k,c_k)。因此总成本逐分量不增，组合结果不劣于任一完整候选。代码用严格下降容差过滤微小变化；相对基线和控制候选的非增保证仍保持，对被舍弃的微小改善只作容差内等价处理。

这个结论依赖于当前动作空间只改路径和同轮分包。若未来允许移动轮次、更换规约贡献或重建发送依赖，就不能直接复用按轮独立组合的论证。该筛选和组合是确定性验收的一部分，其收益不应全部归因于模型。

## 如何检验模型的额外收益

公平比较必须固定当前输入、初始方案、编辑目录和验证器。`tests/edit_ablation.py` 提供同一目录上的确定性整数坐标搜索：它只改变相同的移动数量，独立按官方公式计算成本，并遵守相同的整轮恢复验收规则，最终再经编辑编译器和完整 Replay 验证。它另存原始联合候选成本，避免把筛选收益误当成数量搜索本身的收益。它是有时间预算的启发式对照，没有最优性证书，也不是生产中的假模型替代品。

应同时报告保留基线、确定性数量搜索、模型联合编辑三者的有效率、通信耗时、端到端请求耗时、内存与输出体积。为研究上下文作用，可以进一步比较保留完整共享资源信息和删去该信息的模型输入；各组仍使用完整规则验证，重复运行并保留方差。带宽扰动、方向变化、增删边、重叠资源、节点重命名及未见拓扑用于检查泛化。

[最终真实同目录消融](artifacts/v1.2/live-ablation-final/summary.json) 捕获了实际 SDK 请求使用的冻结基线、完整目录和私有上下文，响应结束后才在同一目录运行 1 秒预算的确定性数量搜索。两例均有效，每例真实调用模型一次，测试期间源码哈希不变，进程限制为单 CPU、1 GiB。成本单位为 μs：

| 实例 | 冻结基线 | 模型编辑阶段返回 | 同目录确定性搜索 | 完整服务最终结果 |
| --- | ---: | ---: | ---: | ---: |
| mesh2d AllGather | 11419.816 | 10542.888 | 8024.097 | 7697.511 |
| mesh2d AllReduce | 217.901 | 217.901 | 165.306 | 159.848 |

AllGather 的模型正向编辑被采用，其移动前缀最终保留；AllReduce 的模型返回全零，没有模型动作被采用。这两次同目录比较中，确定性搜索均优于模型编辑阶段，因此目前不能声称 LLM 强于该确定性方法或证明了长上下文优势。完整服务还包含逐轮合并与更大路径集合上的最终改路，最后一列的全部收益不能归因于模型。这里只是两个公开实例的单次观察。

早期离线网格消融表明扩大合法备用路径集合本身具有收益。下表保留归档实验结果，不代表最新完整服务的性能，也不能归因给 LLM：

| 公开归档基线 | 原 Replay / μs | 全合法单交换机通路贪心 / μs | 同编辑目录的数量搜索 / μs |
| --- | ---: | ---: | ---: |
| mesh2d AllGather | 11280.932 | 7154.771 | 8106.460 |
| mesh2d AllReduce | 217.901 | 159.848 | 165.306 |

前一对照能在每个 pair 的全部合法单交换机通路间选择，动作范围比有限编辑目录更大，因此不能与模型直接作公平胜负比较。后一对照使用提取器给出的相同目录；后续真实模型测试还必须使用同一基线与目录才能归因差异。两者都是公开输入上的本地结果，不是平台隐藏实例成绩。原始记录见 [路径枚举消融](artifacts/mesh-route-enumeration-v1.2.json)、[同目录消融](artifacts/edit-ablation-v1.2.json) 与 [瓶颈分解](artifacts/mesh-bottlenecks-v1.2.json)。

独立对抗覆盖见 `tests/test_edit_invariants.py`：原子守恒、AllReduce 贡献依赖、单向路径、共享资源重复与重叠计费、旧输入/旧方案、越界或未知编辑、提示目录污染隔离，以及合法但更慢的联合动作拒绝。

另有 [首轮 42 个输入扰动回归](artifacts/mutations-v1.2.json)，覆盖七类拓扑、两种算子和三个种子，保留实例名称并修改方向、连边、容量及重叠资源。该轮回归在最终改路阶段接入前运行实际服务、提示构造、数量数组解码和编辑验证，HTTP 模型响应为明确标记的模拟数据。42 个方案均通过本地 Replay，42 个原请求均未被修改，去掉基线标识与哈希后的提示内容也随输入变化；测试进程限制为一个 CPU 和 1 GiB 地址空间。它验证的是实现边界，不是模型能力或官方隐藏实例成绩。

[最终版本 42 个扰动回归](artifacts/mutations-v1.2-final.json) 在按轮筛选、模型与控制轮次合并、最终改路全部接入后重新运行，42/42 有效，源码起止哈希一致。18 个模拟编辑候选被编辑器接受，14 个有轮次最终选中，这 14 个的已选移动前缀全部逐条保留；回归直接捕获编译器产生的完整传输，再与最终传输比较路径、原子分片、端点及动作，并核对实际执行记录。原始输入和去掉标识后的提示内容变化检查也全部通过。仍使用单 CPU、1 GiB 测试进程，峰值 RSS 约 93.28 MiB；模型响应为模拟数据，不能用此测试的耗时估计真实模型请求延迟。
