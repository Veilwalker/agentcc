# AgentCC 1.10：容量建模、模型编写搜索、独立验证

本版的核心是把通信优化分成三个可核验的层次：**工程模块计算真实容量与合法动作，LLM 编写组合搜索代码，独立回放决定是否采纳。** 它是受约束的程序生成，不是让模型直接输出数万条 transfer，也不是由模型重新实现整个求解器。

## 1. 与赛题和师兄建议的关系

正式调整公告将自动榜设为正确性 25、通信性能 50、求解时间 25，单例硬时限六分钟。另收到的评测导向鼓励“分析任务 → 生成或修改求解器代码 → 执行 → 反馈迭代”；详细过程评分仍待公布。不能从六分钟时限推断几秒钟的开销没有代价，也不能把原规则分数直接与重算后的分数相减。

[SmartCCL 论文](materials/research/2026085860-1.txt)及师兄建议启发了容量约束、转发策略生成、冗余消除和调整时间间隔。本项目保留容量建模和后处理思想，不训练神经网络。将可验证的通信阶段作为中间表示，让模型编写阶段组合搜索，取代原先只在固定区段内选择几种编辑的接口。

长上下文可以帮助分析更多约束，但本版使用短输入和运行时成本表；实验不能证明收益来自“长注意力”机制。模型知识的作用是形成可执行的递推程序，实际数值计算交给解释器。后续如果探索模型自由修改路由启发式，应另做受控对照，不能把尚未实现的能力写成成果。

## 2. 与公开 Replay 对齐的容量模型

令路径 p 对边或共享资源 j 的占用次数为 a[j,p]，路径承载字节为 b[p]，容量为 C[j]：

```text
B[j] = Σp a[j,p] × b[p]
T_round = max(
  max_packet(路径开销 + 包字节数 × Σpath(1 / 边带宽)),
  最大路径开销 + max_edge_or_resource(B[j] / C[j])
)
T_comm = Σround T_round
```

规则依据是[共享资源规范](materials/spec/SHARED_RESOURCES.md)与[输出规范](materials/spec/OUTPUT_FORMAT.md)。共享资源可以重叠，同一路径重复经过一个资源要重复计费；方向、成员边和带宽均来自当前输入。内部用微秒，solution.metrics 用秒，最终权威是官方 Judge。

师兄所说的“带宽 × 时间就是容量”对应 B[j] ≤ C[j] × T_round。这里根据负载求每轮需要的时间，不强制一秒一轮，也不把所有共享带宽预先平均分给设备。包沿路径的串行延迟仍单独约束，不能只优化共享池总负载。

## 3. 从固定区段扩大到完整阶段空间

对 N=2^d 个 rank，以 d 个逻辑维度编码通信关系。一次合并 w 个连续维度形成 2^w 路阶段，AllGather 使用 w∈{1,2,3}；AllReduce 对已局部归约的后续阶段允许 w≤5，初始两维仍限制 w≤3，以控制准备成本。逻辑编号不代表物理连边；每个发送关系仍须寻找合法实际路径。

1.6 把维度预先分成较小区段，模型只能改写区段内部。这会漏掉跨区段更好的组合。1.7 建立从位置 i 到 i+w 的有向无环状态图，边权 c[i,w] 是该阶段的实际容量耗时，所有相邻区段组合都可搜索。

AllReduce 的归约和广播分成两个连续区域。模型可给它们不同的阶段划分，但不可跨越语义边界。归约先完成全部贡献合并，再广播完整结果。1.10 扩大后续归约阶段的宽度，并分别计算两个方向的最优划分；每个布局保持同一分片根映射。

物理 rank 顺序候选为输入顺序和当前带宽亲和顺序。二叉成本用于筛掉明显较差的顺序，以限制准备开销；筛选是启发式，不保证被筛掉的顺序不可能产生最优多路方案。

## 4. 完整原子的多路径分流

1.6 的一次发送关系主要使用一条分配后的路径。1.7 将它包含的完整原子分成至多四组，各自按新增边/共享池负载选择路径。AllReduce 的一个贡献表达式不可拆散；AllGather 的一个原始分片不可拆字节。分流区间必须连续、无重叠、无遗漏。

选择依据是当前整轮预计时间，平局再比较负载增量；该路由仍是有界贪心。每个阶段同时保留未分流成本，如果分流反而增加包时延或拥塞，就使用原路径方案。1.10 在初次分配后，以 C++ 对整轮负载做两遍坐标重选：先比较完整轮耗时，再用平方负载打破平台区的平局。结束时重新累计，若数值重建发现退步，则回到初始分配。只有一个原子的发送关系无需重算分流预览。

预览记录原子区间、路径和包大小，编译时照此生成 transfer。两者与独立 Replay 的时间必须一致。有些分流增加输出条数和响应字节，故不能只统计通信收益而不统计完整请求。

## 5. 模型生成什么代码

模型请求先于容量表构建发出，以重叠等待。提示含本次算子、规模、数据大小、切分/轮数约束及代表性有向边和共享容量摘要。全量图不塞进提示；模型代码运行时接收依据全量实际输入计算的成本表。

轮数上限不限制阶段组合时，框架提供初始化、合法前驱枚举和外层循环。模型生成一个组合并选择前驱的 Python 表达式，输入是 `(前驱成本, 前驱路径, 本阶段宽度, 本阶段成本)` 列表。该表达式在每个状态执行，实际决定宽度序列。提示明确描述最小成本递推的任务，但不提供其表达式源码。典型数学关系为：

```text
D[0] = 0
D[i] = min_w (D[i-w] + cost(i-w -> i))
```

若轮数限制有效，需要保留已用轮数 k：`D[i,k]`。此时模型生成完整 `solve(c,limit)` 函数。具体模型代码、原始回复、调用计量都保存，可与最终阶段宽度序列对应。

这两个输入协议不同：通常使用 `incoming_v1`，行 i 表示进入 i 的各前驱代价；受轮数限制时使用 `outgoing_v1`，行 i 表示从 i 出发的合法边，末尾加空终点行。禁止跨越 AR 阶段的边在前者表示为无穷大。两种表都绑定当前输入哈希，并通过测试核对含义。

模型程序决定整个保留阶段空间中的划分，而非给一个稍后被替换的初解做局部改路。若相同结构已由保底获得，或结构空间不适合当前网络，其提案可能不被采用；证据如实记录这一点，不为证明模型有用而接受更慢结果。

## 6. 有界执行与反馈

模型代码不使用 Python 的 `exec` 或 `eval`。专用 AST 数值解释器仅支持必要的循环、条件、索引、列表/字典和数值操作；不支持导入、文件、网络或对象内省，并限制源码、AST、指令数、容器大小及嵌套。输入成本表不可修改。这是一个受限语言执行器，不宣称可以安全运行任意 Python。

执行后先检查返回宽度、总维度、轮数、阶段边界和有限成本，再比较独立成本审计器给出的数值界。审计器只返回该有限空间的最小成本，**不生成替代模型答案**。差距大于 0.1%、代码不合法或编译失败时，若仍在反馈预算内，将错误和成本差距发给模型，最多修正一次；第二次仍失败则保留合法控制。

模型提案只有预计更好才 materialize 并完整 Replay。略差或相等的提案仅完成容量预览检查，会明确标记未进入 Replay，不能说每条模型回复都完整回放过。

## 7. 正确性与保证的边界

- **AG 持有不变量：** 完成 i 个逻辑维度后，rank 拥有对应 2^i 个源的分片；融合 w 维从轮初已存在且互不重叠的源集合取得其余数据。分流只划分这些完整分片，不创造同轮转发依赖。
- **AR 贡献不变量：** 归约节点合并互不相交的贡献集合，所有 rank 的贡献恰好一次进入完整结果；广播只发送完整归约结果。改变阶段宽度不改变每个原子最终根的定义，因此广播可用独立的合法划分。
- **验收不变量：** 方向、路径内部节点、资源占用、持有状态、重复接收、贡献集合、最终结果、切分和轮数都由独立 Replay 检查。仅合法且严格更快的候选替换本次控制。

生产首先保留已验证初解，并预览固定区段内的确定性最小成本组合。预览本身不是已通过 Replay 的方案；只有最终需要采用该组合时才构造 transfers 并完整验证，避免重复编译和回放。当预览耗时不超过初解的 65% 时，跳过旧构造器的继续搜索；其余实例继续运行旧搜索。这个比例是计算预算启发式，并非被跳过候选不可能更优的证明，日志记录初解、比例与是否跳过。后者本身能提高稳定性和部分 AR 性能，不能将该收益归因于 LLM。模型在更宽的空间进行搜索；消融比较应分别列出保底成本、模型成本与最终成本。

“有限空间成本界”仅对保留的顺序、路径、分流粒度和阶段宽度成立，不是物理网络的全局下界。局部路由搜索、顺序筛选、固定切分和有限阶段宽度仍可能限制质量。控制不退步也仅针对本次控制，不保证逐例优于旧版曾经产生的所有模型结果。

## 8. 开销和可核验贡献

完整请求时间需要实测：前处理 + 并行的模型/容量与控制工作 + 编译/回放/响应。模型总时长与 CPU 有重叠，只有未覆盖的等待才直接延长关键路径；输入 Token 与输出 Token 的处理方式不同，不能按统一 token/s 推算延迟，也无法从跨版本记录推出“每省 1000 Token 加几分”。

正常一次调用，最多一次反馈修正，总计至多两次调用。原始交互、生成源码、源码哈希、实际表、逐布局结果、编译验证、采用/拒绝和 Token 均保留。程序固定源码重放、实际图扰动、真实接口重复、无模型增量消融分别测试。温度 0 不保证相同源码；不同源码也可能算出相同方案。

[FunSearch](https://www.nature.com/articles/s41586-023-06924-6)展示了模型生成程序与自动评价结合的研究范式；本项目借鉴该分工，不复现其进化搜索。[TACCL](https://www.usenix.org/conference/nsdi23/presentation/shah)启发受约束的通信结构表达，[ForestColl](https://www.usenix.org/conference/nsdi26/presentation/zhao-liangyu)提示容量与结构需要联合考虑，[TACOS](https://arxiv.org/abs/2304.05301)提供自动合成通信算法的相关路径。各论文的假设和最优性结论不能直接移植到本赛题。

本版可核验贡献是：实际共享容量模型、跨固定区段的阶段搜索、完整原子分流、模型生成搜索代码的执行与反馈、严格保底及完整成本证据。没有证明 LLM 比传统 DP 更优；专家评价应依据这些实际贡献与局限，而不是代码生成或长上下文的标签。

## 9. C++ 的职责与请求成本

1.8 将路径的边/共享资源系数编译、整轮负载维护、候选路径评分迁移至 C++。Python 保留官方运行时、任务解析、通信结构、模型生成代码的受限执行与独立 Replay。后端共享相同的路径对象和评分规则，不改变候选顺序、平局处理、阶段空间或模型提示。

每轮数值状态由独立对象持有，生命周期随 Python 引用结束；没有跨请求的负载缓存。使用双精度并禁用浮点收缩和快速数学变换，避免编译器重新组合表达式改变平局选择。随机差分测试逐次比较选择结果和轮耗时；固定原始模型回复的完整 SDK 请求再比较提示词及最终调度哈希。这些是覆盖范围内的等价证据，不是所有输入上的形式化证明。

扩展在官方基础环境中重新编译，避免依赖开发机的 Python 版本或专用 CPU 指令。正式镜像要求 C++ 成功加载，诊断记录实际后端；Python 参考实现留作测试。没有声称整个系统改写为 C++，也不把同样调度的更快计算称为通信性能提升。

请求关键路径可近似写作 `前处理 + max(模型等待, 容量准备与控制计算) + 后处理`。这仅解释重叠关系，实际还有线程调度、解释器执行与响应序列化。容量计算缩短后，模型等待仍可能决定总时长。因而验证分别记录 CPU、真实模型时长、完整请求及固定等待对照，不能直接用微基准加速比推算平台得分。

## 10. 保持状态等价的持有者重选

AG 已处理 i 个维度后，同一逻辑组的各 rank 持有相同源集合。后续发送该集合时，可以从组内另一持有者发送同一完整原子，不要求一直使用原指定发送者。候选保留原发送者，并按实际直连带宽、共同交换机接入带宽选择至多三个替代者。最终路径的首节点就是实际发送者，Replay 重新检查它在轮初是否持有原子。

只在实际接入交换机数量不超过两个、已处理至少三维且当前扩展一维时启用这一额外搜索，以限制成本。该筛选不依赖拓扑名，不假定缺失连边存在；它也不是全局最优性保证。跨阶段可以选择不同内核，因为每种内核产生的阶段终态相同。

这吸收了师兄建议中的容量约束与转发策略调整，但没有复现论文的神经网络，也没有把贪心模块完整替换成 LLM。路由数值优化和持有者候选仍由工程代码计算；模型贡献是组合搜索程序。对于这种受限代码生成能否获得较高专家分，必须以最终过程评分规则为准。

## 11. 未采用的方向也保留实验

本轮比较了更宽阶段、提前复制部分归约结果、不同分片使用互补维度顺序、旋转逻辑布局、不同归约根间距、更多持有者候选及多路径条数。结果保留在版本分析目录。没有收益或使准备成本过高的方案未进入默认流程。对这些有限实验的否定结果不能外推为该研究方向普遍无效。

## 12. 请求内复用与模型开销实验

阶段内核共享相同的原子移动计数。C++ 在一次整轮调用内部复用同一路径选项的编译结果，每个包仍分别检查字节数和数值边界；请求结束后不保留实例答案缓存。备用方案仅在需要比较或回退时构造，最终采用前仍进行完整 Replay。

测试过更短但含义更模糊的提示、JSON包装以及思考关闭参数：前两者产生错误递推或直接数字答案；思考参数没有稳定降低延迟，网关也没有证明它生效。因此默认保留明确的表达式协议，不通过增加模型调用数来换取表面上的参与。详见版本实验索引。

AllGather 回放只复用已经验证的不可变分片列表到位掩码的转换。发送者轮初持有状态、接收者重复数据和路径合法性仍逐条检查；缓存不跨请求，也不缓存方案有效性。输出长度上限的成对测试未显示稳定的正常请求延迟优势。随后一次真实请求生成了无关长文，128 Token 后截断并触发修复，完整请求达到约9.49秒。因此通常的表达式输出上限降为48 Token（实测正常表达式25～27 Token），用来限制偏题回答的额外生成成本；不据此宣称正常请求一定更快。轮数限制有效、需要完整函数时仍保留512 Token。截断的代码不执行，原始回复和反馈均保留。
