# 1.1 验证与优化记录

规则版本：`agentcc-256-20261101-v22`。代码版本：1.1。测试日期：2026-11-03（Asia/Shanghai）。

## 结果

- 115 项自动测试全部通过：官方 SDK、通信状态、资源重叠、路径、预算恢复、模型证据、并发请求隔离和超时后恢复。
- **21 个真实模型 + 原版官方 SDK 测试全部有效**：14 个公开 256-rank 样例、2 个公开小例、1 个小例共享容量变化，以及 4 个同名 256-rank 拓扑变体。每例 SDK 均记录 1 次模型调用，最终方案再次独立 Replay。
- 最终真实测试只让测试进程使用一个允许的 CPU，并限制地址空间为 1024 MiB；没有执行 Docker。地址空间限制与容器内存 cgroup 不等价。
- 42 个保持连通性的变形输入通过完整服务回归，其中 34 例路径再分配实际改善通信耗时。这组明确模拟模型返回参数，不计为真实模型调用。
- 60 个有效构造器泛化组合全部通过：16/32/64/256 rank、边与资源变化、随机重命名、rank 和边顺序打乱。6 个因随机删边而断连的输入单独记录，不混入有效通过率。
- CloudMatrix 双算子在模拟时钟推进倍率 1、1.5、2、4 的 8 次测试中全部返回有效答案。这是模拟截止更快到达，不是实际 CPU 限速测量。
- 150 个随机有向图、10,800 个路径参数组合与独立原始输入解析及 Bellman–Ford 结果交叉校验。

## 平台异常调查

平台 1.0 得分为 73.4，12/14 有效，CloudMatrix 双算子均报告 `AGENTCC_INVALID_SOLUTION`。平台未提供这两例完整原始请求和响应，不能确认唯一根因。

已独立复现一个足以导致无答案的缺陷：旧版首个模型候选及其重试共享 8 秒预算，较慢环境下在完成第一次 Replay 前预算就已用尽，最终 `best=None` 并抛出错误。保存的 1.0 在模拟两倍时钟推进时，CloudMatrix 双算子均出现 Replay 0 次、无完整答案。

1.1 先完成受保护的首解校验，再进行可放弃的优化。优化超时或可选路径改进失败时保留原有效答案。公开 CloudMatrix 双算子、真实模型的同名边/容量变化输入及压力回归均通过，正式冻结输入仍需平台确认。

## 模型参与与规则核对

每个真实请求都会调用官方模型。输入是当前任务与从实际图数据推导的摘要；完整输入哈希、实际模型请求体、返回参数、候选校验及最终选择均有记录。四个大拓扑变体保留原实例名，改变方向、带宽、边和重叠资源后重新调用模型，输入哈希与请求体改变，方案按新图生成。

预搜索与模型网络等待重叠，模型返回后其参数仍实际构造并验证。模型失败不会伪装成成功；官方 SDK 上下文传播到模型线程，调用次数、Token 和时长对应真实操作。并发请求的状态及计费相互隔离；SDK 超时响应已验证，后台计算依靠内部截止结束。

同轮分包只划分已有完整 chunk 或规约槽位表达式，不制造更小分片。路径时间按各 transfer 计算，边与共享资源字节仍对整轮累计。独立测试证明共享资源主导时，分包不会降低该下界。路径改进按同一资源在路径中出现的次数完整计费，只有成本降低且完整 Replay 有效才采纳。

Token 不直接加扣初赛自动榜分数。榜上的汇总分和 Token 无法证明别人的输出长度、算法或单项成绩；专家与 Token 复核属于用户补充的另外 30% 综合评价。

## 验证边界

宿主机 Python 为 3.10，官方基础镜像 Python 为 3.11；本地使用未经修改的官方 SDK 提取副本。正式入口仍为 `AgentRuntime(MyAgent()).run()`。测试通过官方 ASGI 应用的进程内 HTTP 传输进行，没有实际启动导出的容器镜像。单 CPU 亲和性、1024 MiB 地址空间上限不等于 Docker CPU 配额、内存 cgroup 和 256 pids 限制。

公开样例及生成变体不是正式冻结题库；材料没有官方 Judge 可执行程序和冻结 `L/U/t_good`。本报告不能给出新官方分数，也不把本地通过表述为平台 14/14 通过。
