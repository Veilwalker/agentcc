# 1.3 验证与优化记录

规则版本：`agentcc-256-20261101-v22`。代码版本：1.3。测试日期：2026-11-03（Asia/Shanghai）。**本版尚无官方成绩**。1.1 和 1.2 的平台成绩均显示 92.1；本文本地实验不能换算为新的平台分数。

## 本次结论

在相同公开输入、相同官方 SDK 与模型配置下，三版各重复测量三次，轮换执行顺序。以每个样例的三次中位数为基础，再对14个样例等权统计：

| 指标 | 1.1 | 1.2 | 1.3 |
| --- | ---: | ---: | ---: |
| 请求耗时中位数的样例平均，秒 | 4.045 | 4.668 | **3.440** |
| 单例 Token 中位数的样例平均 | 746.4 | 2440.0 | **1258.4** |
| 三轮42次实际 Token 总量 | 31,366 | 102,510 | **52,843** |
| 本地 Replay 有效请求 | 42/42 | 42/42 | **42/42** |

相对1.2，请求耗时上述统计降低 **26.3%**，实际总 Token 降低 **48.5%**；逐例通信加速比的几何平均为 **1.0104×**。请求时间与Token的14个逐例中位数全部改善；通信有4例改善、5例持平、5例退化。因此这次收益主要来自更短请求与更少Token，通信总体略有改善，不能描述成每一项都更好。

相对1.1，通信14例全部改善，几何平均加速 **1.1378×**；请求上述统计降低 **15.0%**，其中13例改善、cloudmatrix/ag增加约0.303秒。1.3的Token仍比1.1多约68.5%，具体编辑的上下文并未降到旧版只提出构造参数的成本。

完整可交互数据见 [三版本对照报告](artifacts/v1.3/reports/comparison/report.html)，支持指标和版本切换；机器可读数据见 [report.json](artifacts/v1.3/reports/comparison/report.json)。三次重复能提供初步稳定性检查，不能据此估计P95或断言统计显著性。

## 为什么改成现在的流程

用户平台截图显示1.1→1.2的通信分略升、求解时间分下降，逐例展示值平均的总分约下降0.074；一位小数仍是92.1。Token则从10,691增至37,837。这是不同指标的取舍，不能只用通信时间推断总分。

1.3先构造和验证快速初解，提取少量具体编辑组后立即发出模型请求；等待网络期间继续构造、精修和更广的路径搜索。模型候选与已经完成的控制方案比较，只有整体更快或提供更快的兼容轮次才入选。最终不冻结模型动作，不为提高采纳率限制控制方案的路径选择。

提示按实际输入构建共享容量矩阵、合法路径与负载差分，复用重复的资源列，模型仅返回与当前目录绑定的整数数量。编译与校验仍保留完整资源语义和AllReduce原子表达式，不能靠删掉约束缩短提示。已在内部完整验证的报告可以复用，外部输入和潜在赢家仍按规则校验。

离线阶段实验表明，快速初解让模型更早开始，并不意味着总CPU工作必然减少。总体收益依赖网络等待与程序搜索重叠；不能把全部阶段时间直接相加当成请求时间。原始阶段实验见 [搜索阶段对照](artifacts/v1.3/analysis/routing/summary.json)。

## 模型贡献：区分建议、验收和最终采用

42次1.3公开输入请求每次均有1次真实模型调用，其中29次编辑改善初解，**4次最终采用模型具体编辑**。其余请求保留程序搜索结果，完整记录模型原始回复、编译和选择原因。采纳率不是优化目标；不会补造模型数量，也不会为采纳动作让通信变慢。

四次采用发生在三次cloudmatrix/ag和一次cloudmatrix/ar。以其中一次AG为例，模型返回两个组的数量128与48，编译后移动指定轮次中的完整分片；控制候选为25160.535 μs，模型方案为24965.954 μs，最终选择模型方案。这是相对当次已完成控制方案的约0.77%额外改善，不把整个服务的全部收益算给模型。

本次没有证据说明LLM普遍优于确定性调度器，也未验证长注意力的独立贡献。1.2中两次同目录消融的确定性方法更优，负结果仍原样保留。容量推导、原子动作、兼容轮组合和选择不变量详见 [THEORY.md](THEORY.md)。

[全量响应审计](artifacts/v1.3/reports/public-comparison-audit.json) 核对42次最终成本不劣于控制候选、唯一赢家及报告一致性，两批保存的14个输入完全相同。[实际采用证据](artifacts/v1.3/reports/comparison/model-evidence.json) 逐项核对4次采纳中的68条传输及原始模型数量。

## 验证范围

- **231项自动测试通过**，涵盖官方SDK、任务/路径/资源/规约约束、输入变化、严格数量解析、有效报告复用、完整候选选择、兼容轮组合、最终证据、并发隔离以及对照工具。
- **126次三版本真实对照全部有效**：14个公开256-rank输入×3版×3次。每次经官方SDK `/solve`，SDK记录1次真实模型调用，计时结束后再次独立本地Replay；测试期间生产源码哈希不变。
- **7次真实补充请求全部有效**：2个小例、1个小例容量变更和4个保留实例名但修改边/容量/资源的大拓扑变体，每次重新调用模型。1.3正式测试共49次真实调用，合计59,699 Token。先期pilot的12次三版本探索请求另存，不混入正式三轮比较。
- **42个完整服务扰动回归全部有效**：使用明确标记的模拟响应验证工程链路，不联网、不加载凭据。18次提案改善初解，但0次胜过最终控制方案，均正确回退；不能把这组模拟结果作为模型能力证据。真实采用路径另由实际响应与单元测试覆盖。

42例扰动保留实例名并改变有向边、容量和重叠资源，实际提示语义随输入改变，原输入保持不变，最终候选历史只有一个赢家。模拟模式含11次半量、11次八成量、10次未知组、10次无动作。该组最长请求为 2.910秒、进程峰值RSS 95.30 MiB，均不包含真实网络等待。7个真实补充请求的峰值RSS为133.30 MiB；不能据这些输入推断任意拓扑的资源上限。

## 验证边界与交付

宿主机Python3.10使用从官方镜像提取的未经修改SDK，运行原始ASGI应用的进程内HTTP传输。生产入口仍为 `AgentRuntime(MyAgent()).run()`。单CPU亲和性与1GiB进程地址空间限制不等于容器CPU配额、内存和pids限制；基础镜像使用Python3.11。

没有执行Docker、导出镜像或向平台提交。用户按README构建 `agentcc-team:1.3`，导出至 `/home/czy/agentcc-images/agentcc-team-1.3.tar`。Dockerfile只复制 `src/`；`.env`、实验、样例和测试不会进入镜像。

公开材料未提供官方Judge可执行程序及冻结的L/U/t_good，无法在本地计算新官方分数。这里的有效均指公开规则对应的本地Replay；模型、网络与软预算搜索仍会波动，最终综合收益需平台重新评测。
