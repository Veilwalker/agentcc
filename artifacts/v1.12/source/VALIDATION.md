# AgentCC 1.11 / 1.12 验证报告

本轮目标是保留通信结构改善，同时降低完整求解开销。**1.11 是保持1.6调度流程的 C++ 对照；1.12 是继续使用 LLM 生成搜索代码的候选。** 本地已验证工程计算加速与相对旧流程的综合收益，尚未平台送测，没有预填官方分数。

## 1. 先回答1.9为什么慢

实际读取1.6、1.9、1.10导出镜像，核对生产源码、入口、后端和官方Python扩展，未发现错版本。1.6使用Python；1.9/1.10强制C++。同一1.9源码切换后端的84次真实SDK实验中，Python平均完整请求3.465秒、CPU2.212秒，C++为3.236秒、2.026秒。未复现“改成C++导致十秒级变慢”。

但没有平台的完整输入、模型排队、阶段耗时和遥测记录，**不能确定平台额外延迟的唯一原因，也不能断言只是服务器问题**。官方SDK会等待遥测flush后返回，而其内部duration不覆盖全部响应开销。可控实验验证了这一机制，生产代码没有关闭遥测。详见[问题排查](artifacts/v1.11/analysis/diagnosis.md)。

本轮也纠正了测试准备错误：曾有1.10源码目录缺少本机原生扩展，对应实验立即终止、标记无效并重测；发布对照现在拒绝后端与镜像要求不一致的配置。这批无效数据没有进入下表。


打包阶段首次构建还发现1.11快照漏带 `native/round_optimizer.h`。补齐的是1.10原头文件，未修改算法；重新编译后，统一断言中的源码路径，二进制与已测试文件逐字节一致。首轮失败日志与[核对记录](artifacts/v1.11/reports/snapshot-build-reconciliation.json)均保留。该头文件被纳入最终源码清单，镜像从完整快照重建。

## 2. 最终源码的两批完整对照

两批各168请求，合计**336/336有效**。1.6、1.11、1.10、1.12各84次，即14个公开输入、每版每例6次。两批完整输入文件哈希一致，生产源码及二进制哈希在实验前后保持一致。轮换版本顺序；测试期间未并行跑编译或其他CPU实验。

使用官方基础镜像提取的Python3.11、AgentHack SDK和真实授权模型接口。单CPU亲和、1 GiB进程地址空间；通过进程内ASGI调用官方`/solve`，计时包括本次模型等待、本地计算、服务内Replay、SDK返回流程、完整响应序列化及客户端JSON解析。外部独立Replay和落盘在计时外。**这不是容器/cgroup环境，也不包含平台到容器的网络、平台遥测接收器及网关排队条件。**

## 4. 固定回答、波动及模型贡献

[28次固定原始模型回答实验](artifacts/v1.12/runs/numeric-graph-fixed/summary.json)中，1.10和1.12的14个最终调度完全相同，平均CPU1.872 → 1.610秒，减少13.98%。该实验人工使模型立即返回，仅用于隔离执行成本，不能代替真实模型时长。

最终1.12每个输入6次所得调度内容均完全相同，模型代码被最终采用54/84次；其余使用已验证的旧区段候选或控制方案，没有为了显示模型作用采用较差答案。模型主要贡献跨区段、受轮数约束的组合搜索程序；容量计算、路由候选、编译和验证由工程内核完成，不将所有通信收益归于模型。

1.12有2/84次首次回答格式错误，反馈修正后成功：cloudmatrix/ag完整请求7.226秒、模型6.529秒；nvlink_like/ar完整请求5.236秒、模型4.728秒。总调用86次而不是84次，费用与时间已计入。平均14例4381 Token是本次实测，不是每次严格上限。六次重复不足以声称尾延迟已稳定，也不能保证以后不会出现更长排队或坏回答。

## 6. 为什么这次没有只扩大搜索

1.12保留1.10的宽阶段、独立reduce/copy边界、完整原子分流、整轮负载优化及合法持有者替换，主要削减它们的重复执行成本：备用解先精确预览，必要时才展开；已有候选达到有限空间界时在模型等待期间提前验证；C++请求内容量图只构建一次；路径核保持原平局规则；只构造当前AllReduce阶段需要的数据。

师兄建议中的容量建模、逐步转发与消冗思想用于模型和不变量。没有训练神经网络，也没有宣称完全复现论文；LLM生成受约束的搜索片段并接收执行反馈，独立Replay决定能否采用。有限空间最优不等于物理网络全局最优。详见[设计原理](THEORY.md)。

本轮额外做了分阶段循环转发7例、细分AllGather21例、放开单原子搜索28例。大多数没有收益，少数约1%改善伴随0.2～0.75秒开销或响应变大，未进入默认流程。[探索记录](artifacts/v1.12/README.md#未纳入生产的探索)保留失败结果。
