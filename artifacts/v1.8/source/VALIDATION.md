# AgentCC 1.8 验证报告

## 结论：CPU 明显降低，真实完整请求未证明加速

1.8 将容量计算的高频循环迁移到 C++。**相对 1.7，CPU 中位数的样例平均从 3.559 降至 2.589 秒，减少 27.26%；14 个样例都下降。通信调度完全一致。** 官方运行时、LLM 生成搜索代码、搜索空间和 Replay 保持原有流程。

但本轮真实接口测试的**完整请求从 5.920 变为 6.021 秒，增加 0.101 秒（1.71%）**，7 例更快、7 例更慢。不能宣称 1.8 已获得端到端加速，也不能把 CPU 下降直接换算成求解时间分。

同一批条件下，1.6 的完整请求为 3.378 秒，CPU 为 2.194 秒。1.8 仍比它慢：完整请求增加约 2.644 秒，CPU 增加约 0.395 秒。1.8 保留了 1.7 的通信改进与代码生成流程，并没有消除它们的全部代价。旧版本均保留，尚无 1.8 平台成绩。

## 三版真实完整请求对照

[原始记录](artifacts/v1.8/runs/release-sdk/summary.json) · [交互报告](artifacts/v1.8/reports/comparison/report.html) · [统计与稳定性](artifacts/v1.8/reports/release-analysis.json)。14 个公开输入 × 三版 × 各三次，共 **126 次真实模型、官方 SDK 请求，126/126 通过独立 Replay**。运行前后生产源码、C++ 源文件和本地扩展哈希一致。

| 指标 | 1.6 Python | 1.7 Python | 1.8 C++ 核心 |
| --- | ---: | ---: | ---: |
| 完整请求，中位数的样例平均 | 3.378 s | 5.920 s | 6.021 s |
| 请求 CPU，中位数的样例平均 | 2.194 s | 3.559 s | 2.589 s |
| 模型时长，中位数的样例平均 | 2.251 s | 5.516 s | 5.625 s |
| 未被本地工作覆盖的模型等待 | 1.196 s | 2.355 s | 3.435 s |
| 实际 Token 总量除以三，折合 14 例 | 5,146 | 5,917 | 5,955 |
| 模型调用，每个请求 | 1 | 1 | 1 |
| 模型候选进入最终方案 | 35/42 | 27/42 | 27/42 |

模型与 CPU 工作重叠，表中时间不能相加。C++ 让计算更早结束，等待模型的空档因此增加；这不代表又做了额外搜索。本轮 1.8 模型时长也比 1.7 多约 0.109 秒，与完整请求差异接近，但三次重复不足以将全部差异归因于远端服务器。

正常只有一次调用，错误或明显次优时最多反馈修正一次；本轮没有自然触发修正。Token 的小幅差别来自实际模型回复变化，1.8 没有新增模型请求或扩大提示。接口没有提供足够证据判断内部思考模式，不能以字段缺失断言它关闭。

## 测量条件与边界

本轮三版统一使用从官方 `agenthack/base:1.1.1` 归档提取的 **Python 3.11.16 和未经修改的 AgentHack SDK 1.1.1**，在项目内运行；不能与早期开发机 Python 3.10 的绝对秒数直接相减。三版轮换运行顺序，单 CPU 亲和、1 GiB 地址空间，计时期间不并行运行其他 CPU 实验。

计时从官方 SDK 的进程内 HTTP 请求开始，直到完整响应 JSON 解析结束，包含模型、搜索、方案编译、服务内验证、序列化和解析；额外的独立 Replay 与保存文件在计时之外。不包含外部网络传输、容器启动或平台 Judge，也不冒充 Docker cgroup 限制。公开样例与平台冻结输入、评分锚点不同，不预测官方分数。三次重复不足以估计 P95 或证明统计显著性。

## 正确性与兼容性

- 开发机 Python 3.10 完整回归 **439 项通过**：[日志](artifacts/v1.8/reports/unit-host.log)。
- 官方 Python 3.11 完整回归 **439 项通过**：[日志](artifacts/v1.8/reports/unit-image-python-final.log)。原有通信语义、LLM 代码解释与反馈、官方 SDK、资源约束测试均在其中。
- C++ 差分测试含 **6,000 次逐步选路与平局比较**，选择与数值精确一致；另覆盖共享资源重复占用、独立状态、非法参数与强制加载失败。完整公开样例比较进一步检查实际调度，没有只做算术微基准。
- **126/126 真实请求有效**，1.7/1.8 全部调度相同。两版各14例的三次调度也均相同；这不是模型输出永远确定的保证。
- **56/56 固定回复请求有效**，模型提示和最终调度均相同。
- [42/42 拓扑扰动有效](artifacts/v1.8/analysis/mutations.json)：使用已记录程序，保留实例名称、改变边/方向/容量/共享资源，验证按实际输入重算与缺路回退。36例执行模型程序，6例阶段缺路明确回退。这是零模型调用的工程回归，不证明模型重新分析能力。

首次官方环境回归有一项测试工具错误：子进程直接启动提取的解释器，未携带对应动态加载器。原始[失败日志](artifacts/v1.8/reports/unit-image-python.log)保留；修正测试工具后完整439项通过。生产调度不因该问题变更。

## 设计、规则与交付

沿用容量模型、跨区段阶段搜索、完整原子分流和 LLM 生成可执行递推程序。模型生成代码实际读取当前容量表并影响阶段组合，结果必须通过受限执行与独立验证；确定性保底的贡献另行记录，不将所有收益归功于模型。模型作用与消融的背景见 [1.7 发布时验证](artifacts/v1.7/source/VALIDATION.md)，当前实现边界见 [THEORY.md](THEORY.md)。

正式规则仍按已收到的 [25/50/25、六分钟公告](materials/notices/scoring-2026-11-06.md)；另收到的 [LLM 过程导向](materials/notices/llm-process-guidance-2026-11-06.md)详细评分待公布。专家与 Token 复核合占综合成绩30%，不把本地优化等同于专家认可。本轮1.8折合每14例5,955 Token，在用户提出的10,000以内。

最终使用 Python 官方 `AgentRuntime` 和 C++ 容量扩展，不需要 GPU，不训练神经网络。构建阶段安装编译器并在官方基础环境重新编译；最终非 root 镜像检查扩展可加载，运行时不编译、不默默退回 Python。源代码包不包含 `.env`、官方 SDK、材料、实验或本机二进制。

**没有执行 Docker，没有导出镜像，没有上传平台。** 已验证官方归档内解释器与 SDK 的兼容性，但未验证完整 Docker 构建。用户构建、导出方法见 [README.md](README.md)。1.7 的冻结源码和源码包保持原样。
